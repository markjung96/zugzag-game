## 톤 & 무드 (모든 프롬프트 공통)

```
브랜드 톤:
- 클라이밍 짐의 어두운 조명에서도 또렷이 보이는 high-contrast 디자인
- 어두운 배경 기본 (dark mode first), 라이트 모드는 옵션
- 큼직한 타이포그래피, 명확한 정보 위계
- 게임의 짜릿함 + 크루의 따뜻함 (차갑지 않게)
- 클라이밍 홀드 색상(흰/노/주/초/파/빨/보/검)을 액센트로 활용

레퍼런스 느낌:
- Apple Fitness "활동 링" 의 데이터 시각화 명확성
- 게임 leaderboard의 즉각적 위계감
- Strava의 운동 기록 카드의 신뢰감

피해야 할 것:
- 형광/네온 과다 사용
- 작은 글씨로 정보 욱여넣기
- 가벼운 일러스트 일변도 (게임답게 무게감 있게)

타이포: Pretendard (한글) + Inter (영문/숫자)
간격: 4px 그리드, 카드 radius 16px, 버튼 radius 8px
```

```
화면 이름: LiveBoardPage

본문 메인 영역:
- 좌측 65%: Top 10 leaderboard

- 우측 35%: 최근 활동 피드 + "방금 풀이!" 토스트
  - 위에서 카드가 흘러내려옴, 색 도트 + 닉네임 + 풀이 정보, 3초 후 페이드아웃
  - 그 아래로 최근 10건 정적 리스트

배경:
- 어두운 그라데이션 (#0A0A0B → #1A1A1F)
- 미세한 노이즈 텍스처
- 1위 영역에 은은한 그로우

다크 모드 강제. 라이트 모드 안 만듦.
한국어 UI.
```

## P2. 문제 보드 (벽 × 색 그리드)

```
화면 이름: ProblemBoardPage
용도: 현재 세팅 회차의 모든 문제를 한눈에 본다. 모바일에서 가장 자주 보는 화면.
디바이스: 모바일 우선 (375~430), 태블릿/데스크탑은 그리드 확장.

상단:
- 회차 선택 드롭다운 ("2026-05 세팅 (진행 중)")
- 암장 선택 (크루가 여러 암장 다닐 때만 노출)

본문:
- 좌측에 벽 이름 라벨 (sticky)
- 행: 벽 단위. 한 행 안에 그 벽의 모든 active 문제를 색별 → 번호순으로 칩 형태로 표시
- 칩 형태:
  - 배경색 = 그 색상의 실제 hex
  - 텍스트 = 번호 (큰 굵은 폰트)
  - 내가 완등한 문제는 우상단에 작은 체크 아이콘 + 80% opacity
  - 내가 시도했지만 완등 안 한 문제는 점선 테두리
- 칩 탭 → 완등 기록 모달

플로팅 버튼 (FAB):
- 우하단, 큰 + 아이콘
- "완등 기록" 빠른 진입 (벽 직전 선택 기억)

빈 상태:
- "이번 세팅 문제가 아직 없어요" + 크루장에게 알리기 버튼

다크 + 라이트 모드 둘 다 지원. 모바일 PWA 환경 고려.
한국어 UI.
```

## P3. 완등 기록 모달 (3탭 핵심 UX)

```
컴포넌트 이름: SendRecordModal
용도: 사용자가 30초 안에 완등을 기록한다. 손에 초크 묻은 상태에서도 누를 수 있어야 함.
디바이스: 모바일 우선. 풀스크린 모달 또는 바텀시트.

3단계 위저드:

Step 1: 벽 선택
- 그리드 형태 (2~3열). 카드 크기 크게(최소 100×100).
- 직전 선택한 벽은 자동 하이라이트, "다시 그 벽" 빠른 진입 강조
- 각 카드: 벽 이름 + 작은 썸네일(있으면)

Step 2: 색/번호 선택
- 상단에 색 탭 (가로 스크롤). 탭은 실제 색상으로 채워진 큰 원/사각형
- 색 탭 선택 시 그 색의 active 문제 번호들이 큰 그리드로 표시
- 번호 칩은 최소 60×60, 글자 24pt 이상
- "이미 완등" 문제는 회색 처리 + 체크 표시

Step 3: 기록
- 선택한 문제 카드 (벽/색/번호) 상단 요약
- 시도 횟수 입력 (1~99, 숫자 스테퍼). 선택 사항이므로 skip 가능 강조
- 코멘트 (선택), placeholder "한 마디 남기기 (선택)"
- 점수 미리보기: "+95점 (시즌 점수 1240 → 1335)"
- 큰 "기록하기" 버튼 (full width, 높이 56)

전환:
- 단계 간 슬라이드 애니메이션
- 뒤로 가기 명확하게 (상단 좌측 < 또는 chevron)
- 마지막에 성공 토스트 + 라이트한 햅틱

다크 모드 우선. 한국어.
```

## 디자인 산출물 인계 형식

디자인 도구에서 생성한 결과를 zugzag-game 구현에 넘길 때:

1. 화면별 HTML/Tailwind 코드 (또는 컴포넌트 코드)
2. 사용한 색 토큰을 zugzag의 디자인 토큰과 매핑 표
3. 다크 모드 변형이 따로 있다면 둘 다
4. 인터랙션 노트 (애니메이션 타이밍, 트리거 조건)

> 가능하면 zugzag의 `src/app/globals.css`와 `tailwind.config.ts`의 토큰 시스템(이미 디자인 토큰화되어 있음)을 따르도록 부탁. 신규 색은 의도가 명확할 때만.
